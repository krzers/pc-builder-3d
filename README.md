# จัดสเปคคอม 3D

ต้นแบบเว็บจัดสเปคคอมแบบ 3D ภาษาไทย เลือกชิ้นส่วนทีละขั้น โมเดลจะประกอบตามที่เลือก และชิ้นที่ใส่ด้วยกันไม่ได้จะถูกล็อกพร้อมบอกเหตุผล

สถานะ: ต้นแบบสำหรับสาธิต ยังไม่มีราคา สต็อก หรือระบบสั่งซื้อ

## เปิดดู

เว็บที่ deploy แล้ว: https://krzers.github.io/pc-builder-3d/ (อัปเดตเองทุกครั้งที่ push ขึ้น `main` ผ่าน GitHub Actions ใน `.github/workflows/pages.yml`)

หรือเปิดในเครื่อง:

ดับเบิลคลิก `index.html` เปิดในเบราว์เซอร์ได้เลย ต้องมีเน็ตเพื่อโหลด Three.js (r128 จาก cdnjs) และฟอนต์จาก Google Fonts

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ไฟล์ที่ใช้งานจริง สร้างจากสองไฟล์ด้านล่าง **อย่าแก้ไฟล์นี้ตรงๆ** |
| `src/template.html` | โค้ดทั้งหมด (CSS, HTML, JavaScript) มีจุด `/*DATA*/` ไว้ใส่ข้อมูล |
| `data/parts.json` | ข้อมูลชิ้นส่วน 85 รายการที่คัดมาจาก OpenDB |
| `docs/formats.md` | format มาตรฐานในการประกอบคอม และกฎไหนเช็กแล้วหรือยัง |
| `scripts/build.py` | รวม template กับข้อมูลเป็น `index.html` |
| `scripts/build_data.py` | คัดชิ้นส่วนจาก OpenDB มาเป็น `data/parts.json` |

## วิธีแก้แล้วสร้างใหม่

```bash
# แก้ src/template.html หรือ data/parts.json แล้วรัน
python3 scripts/build.py
```

ใช้ Python 3 อย่างเดียว ไม่ต้องติดตั้งอะไรเพิ่ม

## เพิ่มหรือเปลี่ยนชิ้นส่วน

```bash
git clone --depth 1 https://github.com/buildcores/buildcores-open-db
# แก้รายชื่อรุ่นใน scripts/build_data.py (ค้นด้วยบางส่วนของชื่อสินค้า) แล้วรัน
python3 scripts/build_data.py buildcores-open-db/open-db
python3 scripts/build.py
```

ข้อมูลชุดปัจจุบันคัดจาก OpenDB commit `3b64e392` (15 พ.ย. 2026)

## โค้ดใน `src/template.html` แบ่งเป็นส่วนไหนบ้าง

ค้นหาหัวข้อคอมเมนต์เหล่านี้ในไฟล์

- `compatibility rules` กฎเช็กทั้งหมดอยู่ในฟังก์ชัน `pairs(build)` คืนรายการคู่ชิ้นส่วนที่ขัดกันพร้อมข้อความ ส่วน `check(k,item)` ใช้ตัดสินว่าการ์ดใบไหนถูกล็อก
- `item text` ข้อความและสเปคที่แสดงบนการ์ดแต่ละประเภท
- `sound` เสียงทั้งหมดสังเคราะห์ด้วย Web Audio ไม่มีไฟล์เสียง ส่วน `ACC` คือสีประจำแต่ละหมวดชิ้นส่วน
- `UI` การวาดแถบช่องใส่ของ ชั้นวางการ์ด หน้าสรุป และเกจ
- `drag a card onto the stage` การลากการ์ดไปวางบนเครื่อง
- `3D` ฉาก Three.js: ฟังก์ชัน `build...` สร้างโมเดลแต่ละชิ้นจากตัวเลขสเปค, `layout()` คำนวณตำแหน่ง, `sync()` สร้างฉากใหม่จากสเปคปัจจุบัน, `makeThumb()` ถ่ายรูปโมเดลไปใช้บนการ์ด

ลำดับขั้นคือ เคส → เมนบอร์ด → ซีพียู → แรม → การ์ดจอ → ชุดระบายความร้อน → SSD → พาวเวอร์ซัพพลาย ชิ้นจะถูกล็อกเมื่อขัดกับชิ้นใน**ขั้นก่อนหน้า** ถ้าเปลี่ยนชิ้นก่อนหน้าแล้วชิ้นหลังใส่ไม่ได้ ระบบจะถอดชิ้นหลังออกแล้วแจ้งผู้ใช้

## จุดตั้งค่าสำหรับใช้งานจริง

- **ราคา:** เพิ่มช่อง `"p": 12900` (บาท) ให้ชิ้นส่วนใน `data/parts.json` ราคาจะขึ้นบนการ์ดและรวมยอดในหน้าสรุปเอง ชิ้นที่ไม่มี `p` จะไม่แสดงราคา
- **ปุ่มหลักหน้าสรุป:** ตั้ง `CTA.url` ใน `src/template.html` เป็นลิงก์สั่งซื้อ ขอใบเสนอราคา หรือแชต ปุ่มจะขึ้นเป็นปุ่มหลัก ถ้าเว้นว่างจะซ่อน
- **ลิงก์แชร์สเปค:** สเปคปัจจุบันถูกเก็บในส่วนท้ายของ URL (`#b-...`) เปิดลิงก์แล้วได้สเปคเดียวกัน รหัสในลิงก์คือ id ของชิ้นส่วน ถ้าเปลี่ยน id ใน `parts.json` ลิงก์เก่าจะใช้ไม่ได้
- **เสียง:** ปิดเป็นค่าเริ่มต้น ผู้ใช้เปิดเองได้จากปุ่มมุมซ้ายล่าง

## กฎที่เช็กอยู่ตอนนี้

กฎทุกข้อเทียบ format หรือขนาด ไม่เทียบยี่ห้อ รายละเอียด format ทั้งหมดอยู่ใน [docs/formats.md](docs/formats.md)

- ขนาดเมนบอร์ด (Mini-ITX, Micro-ATX, ATX, E-ATX) กับขนาดที่เคสรองรับ
- ความยาวและความหนา (จำนวนช่อง) ของการ์ดจอกับเคส
- ความสูงฮีทซิงก์แบบลมกับเคส
- ช่องเสียบซีพียูกับเมนบอร์ด และกับชุดระบายความร้อน
- ชนิดแรม จำนวนแถว และความจุรวมกับเมนบอร์ด
- ขนาดและความยาวพาวเวอร์ซัพพลายกับเคส
- กำลังไฟ: (TDP ซีพียู + TDP การ์ดจอ + 75 วัตต์) × 1.3 ปัดขึ้นทีละ 50 วัตต์

## ที่ยังไม่ได้ทำ

- ราคาและสต็อกของร้านในไทย (OpenDB ไม่มี)
- คะแนนความแรงของสเปค (ไม่มีข้อมูลเบนช์มาร์ก)
- เช็กตำแหน่งติดตั้งหม้อน้ำของชุดน้ำ (ข้อมูลเคสไม่มีช่องนี้)
- เช็กหัวจ่ายไฟการ์ดจอกับพาวเวอร์ซัพพลาย
- โมเดลเคส เมนบอร์ด ซีพียู SSD และพาวเวอร์ซัพพลายยังเป็นทรงกล่อง (การ์ดจอ แรม ฮีทซิงก์ ละเอียดแล้ว)
- ค้นหาและตัวกรองในรายการชิ้นส่วน
- การลากด้วยนิ้วบนมือถือยังไม่ได้ทดสอบบนเครื่องจริง
